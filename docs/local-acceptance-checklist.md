# Skill Router 本地人工验收清单

本清单用于首版本地运行验收。它只确认本机文件系统结构和应用流程，不把 Codex 或 Claude Code 的真实加载行为算作已验证。

## 1. 启动

1. 在仓库根目录执行 `./scripts/run-local.sh`。
2. 确认应用出现 Skills、项目、更新、系统 Skill、设置五个一级页面。
3. 在“系统 Skill”页面确认 CLI 路径和两个全局入口状态；如有冲突，确认应用没有覆盖原文件。

## 2. 本地套件导入

1. 准备一个父目录，下面放置至少两个各自包含合法 `SKILL.md` 的 Skill 目录。
2. 从“本地目录”导入，勾选其中部分或全部并填写套件名。
3. 确认中央目录为 `~/.skill-router/Library/Suites/<套件>/<skill>/SKILL.md`。
4. 从 Skill 详情使用 Finder 打开，确认应用不提供内容编辑器。

## 3. 项目分发

1. 在“项目”页面加入一个测试项目，选择 Codex、Claude Code或自定义目标。
2. 安装一个或多个中央 Skill。
3. 确认项目目标项是绝对软链接，第一层指向 `~/.skill-router/links/<name>`，稳定入口再指向中央 Skill。
4. 打开项目状态，确认目标、Skill 意图和协调结果可见。
5. 使用“一键添加到 `.gitignore`”，确认只添加当前受管链接的精确路径。
6. 分别验证单项卸载与卸载全部；卸载全部后项目注册和目标配置应保留。

## 4. 公开 Git 更新

1. 输入无需凭据的公开 Git URL，选择候选 Skill 并导入。
2. 在“更新”页面手动检查；有新提交时只显示可更新通知，不预览内容变化或删除项。
3. 确认只有点击“确认并更新中央库”后中央内容才改变。

## 5. 制品

1. 导出单个 Skill 或全部中央内容为 `.skillrouter`。
2. 使用另一临时中央根导入制品，逐项处理同名 Skill 和套件冲突。
3. 确认制品不包含项目路径、项目清单、项目链接、文件书签或 Git 缓存。

## 6. 结构验收边界

验收成功只代表：项目目标项为软链接、绝对指向稳定入口、稳定入口解析到预期中央目录，并且最终目录存在 `SKILL.md`。本清单不启动 Agent，也不证明 Skill 已被 Agent 发现、加载或执行。
