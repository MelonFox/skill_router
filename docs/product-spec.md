# Skill Router 首版产品规格

状态：已冻结  
冻结日期：2026-07-24  
界面修订日期：2026-07-25
产品显示名：Skill Router  
技术标识：`skill-router`

## 1. 文档职责

本文定义 Skill Router 首版必须实现的产品行为、数据边界、用户流程和验收范围。领域术语以 [CONTEXT.md](../CONTEXT.md) 为准；难以逆转的设计取舍以 [ADR 目录](./adr/) 为准。本文与 ADR 冲突时，应先修正文档，不允许实现自行选择其中一个版本。

## 2. 产品定位

Skill Router 是一个只运行在本机的原生 macOS Skill 管理器。它集中保存 Skill 的唯一当前内容，将指定 Skill 以软链接方式分发到不同项目，并提供来源导入、更新检查、项目管理和可移植导出。

产品专注于本地管理，不提供 Skill 发布、市场运营、社交分享或云端同步。用户可以自行同步导出的 `.skillrouter` 制品。

## 3. 首版目标

1. 在 `~/.skill-router/` 建立唯一中央库。
2. 从本地目录或公开 Git 仓库导入一个或多个 Skill。
3. 在中央库中只维护每个 Skill 的一份可变当前内容。
4. 向 Codex、Claude Code 或自定义项目目标分发 Skill，项目中只创建软链接。
5. 允许项目通过全局 `skill-router` 系统 Skill 自助注册和安装中央库中已有 Skill。
6. 检查公开 Git 来源更新，并只在用户确认后应用。
7. 导出和导入包含中央库可移植数据的 `.skillrouter` 制品。
8. 提供 SwiftUI 原生界面和正式、稳定的项目侧 CLI。

## 4. 首版明确不做

- 不保存多个版本，不支持按项目固定版本、回滚或版本比较。
- 不支持应用内创建、复制或编辑 Skill。
- 不支持分类、分组、集合或标签。
- 不支持私有 Git 仓库、SSH、令牌、钥匙串凭据或平台登录。
- 不集成 GitHub、SkillHub、SkillMarket 的搜索、浏览或专用 API。
- 不支持来源变更内容、删除项或受影响项目预览。
- 不支持后台 LaunchAgent、系统通知或应用退出后的检查。
- 不支持应用内自更新。
- 不支持云同步、项目备份或完整应用状态备份。
- 不支持 Mac App Store 和 App Sandbox。
- 不支持 Intel Mac 或 macOS 14 及更早版本。
- 不以真实 Codex/Claude Code 加载作为首版自动验收门禁。
- CLI 不提供中央导入、来源更新、中央删除、导出或系统 Skill 管理。

## 5. 平台与发布边界

- 最低系统：macOS 15。
- 架构：Apple Silicon `arm64`。
- 界面：SwiftUI 为主，必要时局部桥接 AppKit。
- 开发阶段：先保证本机直接构建和运行。
- 对外发布：后续通过 GitHub Releases 提供 Developer ID 签名并经 Apple 公证的非沙盒应用。
- 应用升级：用户手动下载并替换，不在应用内检查或安装新版。

当前开发机已确认是 macOS 15.7.3、`arm64`。已安装并选中 Xcode 26.3（Build 17C529），许可协议和首次启动设置均已完成；当前构建事实源为 Apple Swift 6.2.4 与 macOS 26.2 SDK，部署目标仍为 macOS 15。

## 6. 核心不变量

### 6.1 Skill 身份

- `SKILL.md` 元数据中的 `name` 是全局唯一且不可变的 Skill 身份。
- 名称长度为 1–64，只能使用小写字母、数字和单连字符。
- 名称不能以连字符开头或结尾，不能包含连续连字符。
- 来源目录名可以不同；进入中央库后，目录和分发入口统一使用 `name`。
- 同名 Skill 不能共存，也不能自动覆盖。
- 改名必须在应用外创建新名称、重新导入，再删除旧 Skill。

### 6.2 内容与版本

- 每个托管 Skill 只有一份可变的当前内容。
- 中央库是唯一权威内容源。
- 项目不保存内容副本，只保存指向中央分发入口的软链接。
- 中央更新会立即影响所有引用该 Skill 的项目。

### 6.3 套件与独立 Skill

- 同一次导入只发现一个 Skill 时，导入为独立 Skill。
- 同一次导入发现多个 Skill 时，用户可选择部分或全部，并形成套件。
- Git 套件统一获取和检查更新，但 Skill 按单个选择和分发。
- 本地多 Skill 导入形成不跟踪更新的本地套件。
- 套件名称在中央库内唯一、可编辑，默认使用 Git 仓库名，但不参与 Skill 身份。

## 7. 中央目录结构

首版固定使用以下逻辑结构：

```text
~/.skill-router/
├── state.json                         # 版本化应用状态
├── state.lock                         # 应用与 CLI 共用的排他锁
├── Library/
│   ├── Skills/
│   │   └── <skill-name>/              # 独立 Skill
│   └── Suites/
│       └── <suite-name>/
│           └── <skill-name>/          # 套件内 Skill
├── sources/                           # Git 来源内部区，不直接展示为中央内容
├── links/
│   └── <skill-name> -> ../Library/... # 稳定分发入口
├── system-skills/
│   └── skill-router/
│       └── SKILL.md
├── bin/
│   └── skill-router                   # 配套 CLI
├── journal/                           # 未完成中央写操作
└── staging/                           # 同文件系统暂存内容
```

除已经冻结的 `Library/Skills`、`Library/Suites`、`links` 和 `bin/skill-router` 外，其余内部文件名可在实施时调整，但必须维持相同职责和迁移能力。

## 8. 导入

### 8.1 本地目录导入

1. 用户选择本地目录。
2. 应用递归发现包含可解析 `SKILL.md` 的候选 Skill。
3. 扫描排除版本控制、依赖、构建产物和隐藏目录。
4. 只发现一个候选时，导入为独立本地 Skill。
5. 发现多个候选时，用户选择部分或全部并命名本地套件。
6. 内容复制进入中央库，原目录保持不变且不再跟踪。
7. 导入后的本地 Skill 可由用户通过 Finder 或外部编辑器直接修改中央文件。

### 8.2 公开 Git 导入

1. 用户输入公开 Git 仓库 URL。
2. 首版只跟踪仓库默认分支，不允许选择分支、标签或提交。
3. 应用内部只获取一次仓库，并递归发现候选 Skill。
4. 中央库只呈现用户选择的 Skill，不暴露 `.git`、仓库文档、构建文件或未选择 Skill。
5. 一个候选形成来源独立 Skill，多个候选形成来源套件。
6. 来源 Skill 在产品语义上只读，但不通过文件权限阻止外部修改。
7. 用户直接修改来源 Skill 后，后续来源更新可以无条件覆盖该修改。

### 8.3 候选最低校验

- 必须有可解析的 `SKILL.md`。
- 必须包含符合名称规则的 `name`。
- 其他元数据原样保留，不作为中央库通用合法性的前置条件。
- Codex、Claude Code 或自定义目标的附加要求由目标模板在分发时判断。

### 8.4 链接与来源信任

- 导入和更新原样保留来源中的所有软链接。
- 越出 Skill 或套件范围、指向绝对路径或当前断开的链接都不导致导入失败。
- 产品不维护来源信任状态，也不弹出来源信任确认。
- 用户输入 Git URL 即视为授权该来源；来源安全责任由用户承担。

### 8.5 导入冲突

- Skill 名称冲突：逐项选择“替换”或“跳过”，其余无冲突项继续导入。
- 替换同名 Skill 后，原稳定分发入口不变，项目立即使用新内容。
- 套件同名但来源不同：必须重命名待导入套件或跳过，不能合并或替换现有套件。

## 9. 项目与分发

### 9.1 项目身份

- 已注册项目以本机规范化绝对路径区分。
- 不同克隆和 Git worktree 是不同项目。
- macOS 文件书签只用于尽量跟踪同目录移动或改名。
- 项目也可以不是 Git 仓库。

### 9.2 项目清单

项目根目录使用 `.skill-router.json` 保存期望状态：

```json
{
  "schemaVersion": 1,
  "targets": {
    "codex": {
      "type": "codex",
      "path": ".agents/skills"
    },
    "claude-code": {
      "type": "claude-code",
      "path": ".claude/skills"
    }
  },
  "skills": {
    "example-skill": {
      "targets": ["codex", "claude-code"]
    }
  }
}
```

示例表达冻结的数据关系，不冻结 JSON 键的最终内部命名；实施时必须提供 `schemaVersion`、稳定迁移和相同语义。

- 项目清单是权威期望状态，可提交到 Git。
- 软链接是本机生成物，不应提交。
- 应用不自动修改 `.gitignore`，但提供精确忽略项和一键添加。

### 9.3 分发目标

- 一个项目可以登记多个目标。
- 首版内置 Codex 与 Claude Code，并允许自定义项目相对路径。
- Codex 项目目标：`.agents/skills`；全局目标：`~/.agents/skills`。
- Claude Code 项目目标：`.claude/skills`；全局目标：`~/.claude/skills`。
- 从界面加入项目时，应用检测已存在目标目录并预选，用户确认前不创建目录。
- 从项目请求 Skill 发起且未指定目标时，只使用当前 Agent 目标；目标不存在时自动登记。
- 检测到 Agent 版本可能不支持软链接时只警告，仍执行分发。

### 9.4 链接结构

项目中的每个受管 Skill 使用绝对软链接：

```text
<project>/<target>/<skill-name>
  -> /Users/<user>/.skill-router/links/<skill-name>
  -> ~/.skill-router/Library/Skills/<skill-name>
     或 ~/.skill-router/Library/Suites/<suite>/<skill-name>
```

项目移动不影响绝对链接；换机后旧链接不可移植，必须通过项目清单重新协调。

### 9.5 冲突与部分完成

- 正确受管链接视为成功。
- 损坏的受管链接可以修复。
- 同名的不受管文件、目录或软链接形成分发冲突，绝不自动覆盖或静默跳过。
- 批量请求中不存在于中央库的名称不写入清单，其他有效名称继续处理。
- 有效意图先原子写入项目清单，再逐项协调链接。
- 目标冲突或兼容错误保留为待协调分发。
- 部分完成必须返回非零状态并逐项说明。

### 9.6 协调

项目协调在以下时机显式运行：

- 应用打开；
- 项目被选中；
- 用户手动刷新；
- CLI 执行相关命令。

首版不持续监听项目清单。项目偏差通过重新扫描派生，不维护持久后台清理队列。

### 9.7 项目移除与卸载

- 取消注册只移除本机项目记录，不修改项目清单或现有链接。
- “卸载全部”清空项目清单中的 Skill 意图并删除受管链接，但保留项目清单、目标配置和项目注册。
- 单个项目 Skill 可以从界面或正式 CLI 卸载，但项目请求系统 Skill 不提供卸载能力。

## 10. 项目请求系统 Skill

### 10.1 安装

首次启动时自动执行：

1. 创建 `~/.skill-router/`。
2. 安装 `~/.skill-router/bin/skill-router`。
3. 安装系统 Skill `skill-router`。
4. 在 `~/.agents/skills/skill-router` 和 `~/.claude/skills/skill-router` 建立全局入口。

用户之后可以从设置停用或修复系统 Skill，但不能编辑或删除其内置内容。

### 10.2 首版能力

系统 Skill 只负责：

1. 当前项目尚未注册时注册当前工作目录。
2. 向当前 Agent 目标安装用户指定的一个或多个中央库既有 Skill。

系统 Skill 不卸载项目 Skill，不导入来源，不搜索市场，不更新或删除中央内容。它通过绝对路径调用 `~/.skill-router/bin/skill-router`，不依赖 `PATH`，原生应用无需运行。

## 11. 来源更新与删除

### 11.1 检查与通知

- 只在应用运行时检查。
- 启动时检查一次，之后每 24 小时最多自动检查一次。
- 用户可以手动刷新。
- 可更新项只在“设置 > 来源更新”中显示，不在侧边栏显示徽标。
- 不申请系统通知权限，不弹出模态窗口。
- 通知不展示内容差异、删除 Skill 或受影响项目。

### 11.2 应用更新

- 用户按来源套件或来源独立 Skill 分别确认。
- 不支持套件内逐 Skill 更新。
- 用户确认后中央库才改变。
- 中央更新先提交，再尽力修改所有受影响项目。
- 单个项目不可写或清理失败不回滚中央更新。

### 11.3 上游移除和手动删除

- 上游删除来源 Skill 时，中央库立即删除该 Skill，不保留最后内容。
- 删除会尽力从所有项目清单和分发目标级联移除。
- 手动删除中央 Skill 使用相同级联规则。
- 单个项目清理失败不回滚中央删除；后续扫描显示项目偏差并允许手动协调。
- 上游改名等价于旧名称被删除并出现新候选，新候选不自动导入。

## 12. 导出与导入制品

- 导出全部或用户选择的 Skill/套件。
- 制品扩展名为 `.skillrouter`，底层为 ZIP。
- 内含版本化 JSON 清单、Skill 内容、来源关系和逐文件完整性校验值。
- 不包含项目路径、项目清单、项目链接、macOS 文件书签或内部 Git 缓存。
- 导入前必须校验制品结构、版本和完整性。
- 同名 Skill 逐项替换或跳过。
- 同名异源套件要求重命名或跳过。
- 用户自行通过 Git、网盘或其他方式同步制品；应用不提供同步服务。

## 13. 原生界面

一级侧边栏：

1. 技能
2. 项目
3. 设置

技能和项目主区使用统一的标题、说明、搜索、列表行和状态组件；详情在点击条目后以弹窗显示，不常驻占用主区。来源更新与系统 Skill 管理归入设置。必须支持：

- 从 Skill 查看来源、套件、当前状态和引用项目；
- 从项目查看目标、Skill 意图、链接状态、冲突和偏差；
- 导入本地目录和公开 Git URL；
- 导出/导入 `.skillrouter`；
- 应用来源更新和中央删除；
- 注册、取消注册和协调项目；
- 管理系统 Skill 安装状态；
- 打开 `~/.skill-router/` 或具体 Skill 的 Finder 位置。

界面支持跟随系统、浅色和深色三种外观；主操作使用中性色，不以蓝色作为品牌主操作色。低频或破坏性操作集中在详情弹窗的“更多”菜单。相同功能组件不得在页面内重复实现。

首版不提供创建向导或编辑器。

## 14. CLI 契约

### 14.1 定位与范围

- 固定路径：`~/.skill-router/bin/skill-router`。
- 是正式稳定接口，不是应用私有脚本。
- 首版仅覆盖项目注册、列表、状态、安装、卸载和协调。
- 原生应用与 CLI 必须调用同一核心库。

建议的首版命令面：

```text
skill-router project register [--path <path>] [--target <target>]
skill-router project list
skill-router project status [--path <path>]
skill-router project install <skill>... [--path <path>] [--target <target>]
skill-router project uninstall <skill>... [--path <path>] [--target <target>]
skill-router project reconcile [--path <path>]
```

命令拼写可以在实现首个公开版本前调整；一旦发布即受兼容承诺约束。

### 14.2 输出

- 默认输出简洁中文。
- `--json` 输出带结构版本的 JSON。
- 正常结果写 stdout，诊断写 stderr。
- 完全成功退出码为 0。
- 部分完成、校验失败、冲突、忙碌和内部失败使用可区分的非零退出码。

### 14.3 并发

- 原生应用和 CLI 使用同一个排他文件锁。
- 写操作最多等待约 5 秒。
- 超时返回“Skill Router 正忙”，不无限等待。
- 不通过正在运行的应用转发 CLI 请求。

## 15. 状态、事务与恢复

- 应用元数据使用带 `schemaVersion` 的 JSON 文件，不使用 SQLite 或 SwiftData。
- 写入使用同目录暂存和原子替换。
- 中央导入、替换和更新先写轻量操作日志，再写暂存内容并原子切换。
- 应用或 CLI 下次运行时必须先恢复或清理未完成操作。
- 项目清单和项目链接不纳入中央事务，通过项目协调恢复。
- 状态文件损坏、未知 schema 或无法恢复的事务必须停止写入并给出可操作错误，不能静默重建覆盖用户数据。

## 16. 安全与数据边界

- 进程使用当前用户普通文件权限运行，仍受 POSIX、TCC 和 SIP 限制。
- 不请求管理员权限。
- 不启用 App Sandbox。
- 不保存 Git 凭据。
- 外部来源可能包含脚本和越界软链接；产品不进行信任确认或沙盒执行。
- 不受管项目文件永不自动覆盖或删除。
- 只有仍可确认属于 Skill Router 的受管链接才能自动修复或清理。

## 17. 自动测试与验收边界

自动测试必须在独立临时根目录运行，不得修改真实 `~/.skill-router` 或真实项目。

必须覆盖：

- `SKILL.md` 解析、名称约束和候选发现；
- 本地独立 Skill、本地套件、Git 独立 Skill 和 Git 套件导入；
- 同名替换、跳过和套件冲突；
- 项目清单编解码、迁移和批量部分完成；
- 目标兼容错误、警告和不受管路径冲突；
- 完整双层软链接链路；
- 项目协调、取消注册、单项卸载和卸载全部；
- 来源更新、删除、级联清理失败和项目偏差；
- 文件锁、忙碌超时和事务恢复；
- `.skillrouter` 导出、完整性失败和导入冲突；
- CLI 中文/JSON 输出、stdout/stderr 和退出码。

结构验收必须确认：

1. 项目目标项确实是软链接；
2. 链接使用绝对路径指向 `~/.skill-router/links/<name>`；
3. 稳定入口继续解析到预期中央 Skill；
4. 最终目录存在 `SKILL.md`；
5. 没有用复制内容替代软链接。

自动测试不启动 Codex 或 Claude Code，不证明 Agent 已发现、加载或执行 Skill。所有报告必须把“分发成功”限定为文件系统结构正确。

## 18. 已知风险

1. 不保存版本意味着来源错误更新或误替换无法由应用回滚。
2. 更新无差异预览，但上游删除会级联修改多个项目清单。
3. 中央更新不因项目清理失败回滚，可能产生需要协调的项目偏差。
4. 来源软链接不受限制且无信任确认，可能暴露中央库外文件。
5. 来源 Skill 只在产品语义上只读，外部修改可能在更新时丢失。
6. 不支持私有仓库，企业来源覆盖有限。
7. 绝对项目链接不可跨机器直接使用，必须依赖清单重建。
8. 结构测试不能证明目标 Agent 实际可用。
9. JSON 单文件状态适合首版规模，但并发和大规模查询能力有限。
